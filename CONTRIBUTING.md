# Contributing to Float PiP

Thanks for helping Qurkos make video controls simpler. You can contribute by reporting reproducible bugs, checking browser compatibility, improving accessibility, writing documentation or sending a pull request.

## Before starting

Search existing issues. For a significant feature or permission change, open an issue first so we can agree on scope. Small fixes and documentation improvements can go straight to a pull request. Follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Development

Fork this repository, clone your fork and create a descriptive branch. Python 3.9+ and Node 18+ are sufficient; no dependency installation is needed for the normal build.

```sh
node --test tests/*.test.cjs
python3 tools/build.py
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

Load the generated extension from `dist/packages/` in your browser. Check the behavior you changed in a real installed extension. Record browser version, operating system, expected behavior and observed behavior. Never include credentials, account tokens or private streaming footage in reports.

## Project map

- `extension/player.js`: injected video discovery and PiP controller.
- `extension/popup.js`: popup scanning and interaction.
- `extension/`: readable UI, help, icons and default Chromium manifest.
- `tools/build.py`: deterministic manifests, icons and packages.
- `tests/`: Node behavior tests and Python package checks.
- `docs/`: privacy policy, publishing and test evidence.

Manifests and icons are generated by `tools/build.py`; change that generator when changing them. Keep the Firefox add-on ID stable. For version changes, update `package.json` and all version values/output names in `tools/build.py` together.

## Pull requests

Explain the problem, what changed and how you tested it. Link the relevant issue. Keep changes focused, add meaningful regression coverage for behavior changes, and update documentation when behavior changes. Do not commit `dist/`, local browser profiles, dependencies or credentials.

Preserve temporary permissions and the no-data design. Permission, data handling and remote-code changes require explicit discussion and corresponding privacy/documentation updates. Do not claim compatibility with a service without actual testing.

Contributions are accepted under this repository's MIT license. No contributor license agreement is required. Maintainers review contributions; response times are not guaranteed.
